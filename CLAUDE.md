# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Reglas del dueño del proyecto

- **No hagas commits, pushes ni pull requests.** Deja los cambios sin commitear; Max los revisa y commitea él mismo.
- Todo está en español: código (funciones, variables), comentarios, mensajes de la CLI, README y tests. Los usuarios no son técnicos, así que los mensajes en pantalla y el README usan lenguaje simple.
- Cada archivo empieza con un comentario `# Ubicación: ruta/del/archivo.py` y una explicación corta de qué hace. Los comentarios explican el *porqué*; mantén esa densidad.
- El entorno se maneja con `uv` (Python 3.11 en el `.venv` de Max). Da comandos `uv pip ...`, no `pip ...`.

## Comandos

```bash
# Entorno de desarrollo
uv venv && source .venv/bin/activate
uv pip install -e ".[diarizacion]"              # los extras que no aplican a la plataforma se saltan solos
uv pip install -r requirements-dev.txt          # solo para tests

# Tests (no necesitan red, GPU ni modelos)
python -m pytest
python -m pytest tests/test_diarizer.py
python -m pytest tests/test_repeticiones.py::test_quita_los_bucles
python -m pytest -k hablantes

# Ejecutar
transcriptor                     # menú con flechas (solo en terminal interactiva; si no, muestra la ayuda)
transcriptor transcribir ARCHIVO_O_URL -m small -d
transcriptor nombres audio.blocks.json -e
python main.py ...               # equivalente; main.py solo llama a src.cli:app
```

No hay linter configurado. CI (`.github/workflows/tests.yml`, en cada push y pull request) corre `pytest` en Ubuntu con Python 3.10 y 3.12 (y en `windows-latest` con 3.12, con `continue-on-error`: no pone el check en rojo mientras se ve cuántas pruebas fallan por diferencias de Windows) instalando **solo** `requirements-dev.txt`: cualquier import de mlx, pyannote, faster-whisper, yt-dlp o numpy pesado a nivel de módulo rompe CI. Esas librerías se importan dentro de las funciones (buscar "Importación diferida").

## Arquitectura

Versión actual: `2.0.0b2` ("V2-beta2", en `pyproject.toml`). Los instaladores bajan `main`; la beta vive en la rama `v2` (la crea y publica Max).

Flujo: entrada (URL o archivo) → descarga (yt-dlp) → Whisper → limpieza de bucles → párrafos → `.blocks.txt` → (opcional) diarización → `.blocks.json` + `.blocks.txt` con hablantes.

Capas:
- `src/cli.py` (Typer + Rich): todo lo que se ve en pantalla, comandos `transcribir` y `nombres`. Barras de progreso en `_Pasos`. `ejecutar_transcripcion` envuelve el trabajo en `aviso.sin_dormir()` (siempre) y `aviso.confirmar_cancelar()` (solo con una persona delante: no `--sin-preguntas` y terminal interactiva), y notifica al terminar si pasó más de `SEGUNDOS_TRABAJO_LARGO` (60 s). `_escuchar_y_nombrar` es el paso de poner nombres con flechas (Ponerle nombre / Escuchar otra vez / Otro fragmento / Es la misma persona que… / Dejar como está; con sugerencia por voz, «Es <nombre>» va primero). `_mostrar_error` traduce el error con `errores.mensaje_simple` y guarda el detalle siempre (ya no hace falta `-v`; `-v` sigue mostrando el traceback y los logs). `cli.ultimo_error` guarda la ruta de ese detalle para el menú.
- `src/menu.py` (questionary): solo hace preguntas y luego llama a las mismas funciones de `cli.py` (p. ej. `cli.ejecutar_transcripcion`). "← Volver"/Esc lanza `Atras`; Ctrl+C vuelve al menú principal. «Transcribir» son 3 pasos encadenados con `seguir_pasos` (entrada: un solo campo que distingue archivo o URL; una sola pregunta de hablantes, que respeta `modo_hablantes`; nombre de la reunión, propuesta `<fecha de grabación> Reunión`) y «¿Empiezo?» con «Más opciones…» (modelo, idioma, carpeta solo para esa vez). Tras un error, `_que_hago_con_el_error` ofrece Ver el detalle / Copiar el error / Volver al menú. «Copiar la transcripción» está en `acciones_sobre` («¿Y ahora?» y «Mis transcripciones»). Ya no existe la opción de menú «Usar los nombres que edité a mano en el .json» (el comando `nombres ARCHIVO` sin lista sigue).
- `src/aviso.py`: cosas del sistema operativo, solo con librería estándar y sin lanzar nunca errores: `sin_dormir()` (Mac `caffeinate -i -w <pid>`; Windows `SetThreadExecutionState` por ctypes), `notificar()` (Mac `osascript`; Windows PowerShell con la API de avisos + `winsound`; Linux `notify-send`), `copiar_al_portapapeles()` (`pbcopy`; Windows `Set-Clipboard` leyendo un archivo temporal UTF-8; Linux `wl-copy`/`xclip`) y `confirmar_cancelar()` (segundo Ctrl+C pasado el primer minuto). El texto del usuario viaja a PowerShell por variables de entorno, nunca pegado en el script. Lo de Windows no se ha probado en un Windows real.
- `src/errores.py`: `mensaje_simple` traduce los errores comunes (falta `HF_TOKEN`, sin internet, archivo que no es audio, disco lleno, archivo no encontrado) y `guardar_detalle` escribe `~/.transcriptor/errores/AAAA-MM-DD_HHMMSS.txt` (versión, sistema, comando, traceback; sin variables de entorno, con el token tapado; se conservan los últimos 30).
- `src/voces.py`: reconocimiento por voz. Guarda en `voces.json` la huella (embedding de pyannote, centroide por hablante) de cada persona nombrada y `parecidos()` compara por similitud coseno contra `UMBRAL` (0.6, **provisional**: hay que ajustarlo con reuniones reales). Python puro, sin numpy. Solo propone: cada sugerencia se confirma al nombrar. Se apaga con el ajuste `reconocer_voces`.
- `src/procesador.py`: orquesta el flujo sin imprimir nada; informa avance con callbacks (`al_avanzar`, `al_progresar`, `al_fallar`) y devuelve un `Resultado`. `procesar_entrada(continuar_sin_hablantes=True)` (lo pasa la CLI con `--sin-preguntas` o sin terminal interactiva) hace que, si falla preparar pyannote (sin clave, sin internet), se transcriba igual y el error quede en `Resultado.error_hablantes`; con una persona delante sigue fallando rápido. El TXT se guarda **antes** de diarizar para no perderlo si la diarización falla; si falla, la transcripción queda sin hablantes y no es un error.
- `src/transcriber.py`: dos motores con los mismos nombres de modelo (`MODELOS_MLX` / `MODELOS_FASTER`): mlx-whisper en Mac con chip Apple, faster-whisper en Windows/Linux/Mac Intel. `motor()` decide según si `mlx_whisper` se pudo importar. `AJUSTES_CONTRA_BUCLES` (sin condicionar en texto previo, timestamps por palabra, saltar alucinaciones en silencios) es deliberado.
- `src/repeticiones.py`: quita sin IA las frases que Whisper repite en bucle, en segmentos y en párrafos.
- `src/diarizer.py`: pyannote. `asignar_hablantes` usa los timestamps por palabra para dar cada frase completa al hablante mayoritario. El `.blocks.json` guarda las etiquetas genéricas ("Hablante 1") y el mapa `nombres` aparte, para poder renombrar sin reprocesar (`procesador.renombrar_hablantes`). `diarizar_audio` también saca las huellas de voz (`speaker_embeddings` de pyannote 4) y `traducir_huellas` las pasa de `SPEAKER_00` a "Hablante N"; sin huellas la diarización sigue igual.
- `src/vista.py`: «Leer con el audio». Arma un HTML de un solo archivo (sin red ni librerías) desde el `.blocks.json` (con nombres) o, si no hay, desde el `.txt`, y lo guarda en `~/.transcriptor/vistas/` (no ensucia la carpeta de la reunión). El texto del usuario viaja como JSON escapado y el DOM se arma con `textContent`, nunca pegado en el HTML. Sin audio se ve igual, sin reproductor.
- `src/buscar.py`: «Buscar en todas». Sin tildes ni mayúsculas, todas las palabras en el mismo párrafo; devuelve `Coincidencia` (reunión, minuto, hablante, fragmento). No imprime ni pregunta.
- `src/dudosas.py`: frases de hablante dudoso. `diarizer`/`transcriber` las marcan como clave `dudosas` del párrafo en el `.blocks.json` (el otro hablante posible); el `.txt` no cambia. Para `.json` antiguos se infieren (párrafos muy cortos entre dos de otra persona). `mover_frase`/`marcar_bien` corrigen y `guardar` rehace el `.txt` (con encabezado si lo tenía). La revisión con flechas vive en `cli._revisar_dudosas`.
- `src/modelos.py`: modelos de Hugging Face (Whisper y pyannote) y la clave. Usa la caché de `huggingface_hub` para saber qué está descargado, cuánto pesa, descargar con avance y eliminar; `guardar_token` escribe en `~/.transcriptor/.env`. `procesador` lee el token en el momento (`_token_actual`), así que guardarlo desde el menú vale sin reiniciar. «Preparar la app» = clave + modelo por defecto + modelo de hablantes.
- `src/actualizar.py`: «Buscar actualizaciones». Compara la versión instalada con el `pyproject.toml` de `main` y, si se usa la beta, también el de `v2`; `actualizar()` primero fija el commit (API de GitHub con `Accept: application/vnd.github.sha`), baja `archive/<sha>.zip`, lo revisa en Python (una sola carpeta raíz, sin rutas peligrosas, tamaño máximo, y la versión de su `pyproject.toml` debe ser la anunciada y más nueva que la instalada) y solo entonces corre el mismo `uv tool install` del instalador sobre ese archivo local. No puede evitar que alguien con permiso de push a la rama publique algo malo: no hay firma ni hash del dueño. En Windows el programa abierto no se puede reemplazar: la descarga y la revisión las hace Python antes; lanza una ventana aparte (el .ps1 recibe la ruta del zip por `TRANSCRIPTOR_ZIP` y no descarga nada) que espera a que se cierre y luego instala (sin probar en un Windows real). Solo librería estándar; el aviso en el menú se busca en segundo plano como mucho una vez por semana y nunca con «Sin internet».
- `src/clic_derecho.py`: «Transcribir con clic derecho». Mac: crea una acción de Automator (`.workflow`, escrito a mano: probar en un Mac real) en `~/Library/Services`; Windows: un acceso directo `Transcriptor.lnk` en «Enviar a», creado con PowerShell (WScript.Shell, datos por variables de entorno) que apunta al programa con el argumento `en-fila`; no pasa por cmd porque con un `.cmd` y `%*` un archivo llamado `a&b.mp3` se interpretaba como comandos. `migrar_si_hace_falta()` (se llama al arrancar, salvo en `en-fila`) cambia solo el `.cmd` antiguo por el `.lnk`. Ambos llaman al comando oculto `transcriptor en-fila ARCHIVO...` (`cli.en_fila`), que transcribe uno tras otro con los ajustes. En Mac la acción escribe un `.command` temporal (programa y archivos entre comillas con `${(q)@}`) y lo abre con `open -a Terminal`: así se ve el avance y, con terminal interactiva, `en-fila` ofrece nombres y frases dudosas como el menú (sin terminal no pregunta y avisa con notificación). En Windows la ventana del acceso directo hace lo mismo y espera Enter al final. Un candado `~/.transcriptor/fila.lock` (bloqueo del sistema sobre un archivo abierto: `fcntl.flock` / `msvcrt.locking`, que se suelta solo si el proceso muere) hace que varios lanzamientos esperen su turno; `en_fila` lo toma por archivo y lo suelta antes de las preguntas. Devuelve bool y nunca lanza.
- `src/plataforma.py`: qué funciona en cada computador (hablantes: no en Mac Intel) y el sistema operativo: `es_windows()`, `es_mac()`, `es_linux()`. Úsalos en vez de comparar `sys.platform` a mano, así los tests lo simulan en un solo sitio (excepciones: `config.py` y `rutas_windows.py`, que corren antes o sin importar el resto). Las mismas restricciones están como marcadores de plataforma en `pyproject.toml`.
- `src/sistema.py`: `abrir(ruta)` (mostrar el archivo/carpeta en el explorador del computador) y `abrir_pagina(url)` (navegador), compartidos por el menú y «Leer con el audio». Nunca lanzan; sin programa para abrir, muestran la ruta.
- Configuración en tres niveles, de menor a mayor prioridad: `src/config.py` (lee con rutas explícitas el `.env` de la raíz del proyecto, si existe, y luego `~/.transcriptor/.env`; no busca `.env` en carpetas superiores; también apaga la telemetría de pyannote/HF) → `src/ajustes.py` (menú "Configuración", guardado en `preferencias.json`) → opciones de la línea de comandos. `ajustes.aplicar_sin_internet()` pone `HF_HUB_OFFLINE` y debe correr antes de que se importe `huggingface_hub`.
- `src/historial.py`: historial, preferencias y personas en `~/.transcriptor/` (o `$TRANSCRIPTOR_HOME`). La carpeta es 0700 y los archivos de datos (`historial.json`, `preferencias.json`, `personas.json`, `voces.json`, `vistas/`, `errores/`, `.env`) se escriben 0600 con `archivos.escribir_*(privado=True)`; los `.txt`/`.json` junto al audio siguen con permisos normales (los lee el Grabador). Archivos que viven ahí: `.env`, `historial.json`, `preferencias.json`, `personas.json` (nombres usados, con veces y última vez, para elegirlos de una lista), `voces.json` (huellas de voz; **solo en el computador**, nunca se envían), `errores/` (detalle de cada error), `vistas/` (páginas de «Leer con el audio»), `fila.lock` (candado de `en-fila`) y `bin/` (ffmpeg).
- `src/rutas_windows.py`: en Windows un programa lanzado por nombre se busca primero en la carpeta actual (puede ser la del audio), así que se usan rutas completas: `powershell()`, `explorer()` y `buscar_programa(nombre)` (como `shutil.which` pero ignorando la carpeta actual en Windows). `config.py` además pone `NoDefaultCurrentDirectoryInExePath=1` en Windows. Nada de esto se ha probado en un Windows real.
- `src/entorno.py`: `sin_secretos()` devuelve el entorno sin `HF_TOKEN` (y variantes); se pasa como `env=` a los programas que lanzamos (aviso, fragmentos, clic derecho, abrir, actualizar). yt-dlp y los motores de Whisper heredan el entorno completo.
- `src/ffmpeg_local.py`: si no hay `ffmpeg` en el PATH, enlaza el de imageio-ffmpeg en `~/.transcriptor/bin`.
- `utils/formatters.py`: formato de `.blocks.txt` (`[HH:MM:SS] Hablante: texto`, `format_timestamp_hhmmss`: contrato del Grabador, no tocar), `formato_reloj` (`m:ss`/`h:mm:ss` para pantalla), `formato_duracion` (texto corto de duración) y lectura/escritura del `.blocks.json`.
- `utils/validators.py`: `es_url` y `limpiar_ruta` (quita comillas y escapes de una ruta pegada o arrastrada).
- `utils/archivos.py`: escritura atómica (`escribir_texto`, `escribir_json`: temporal único en la misma carpeta, fsync, `os.replace` con reintentos en Windows) y `leer_json`, que tolera BOM y, si el archivo está dañado, lo aparta como `<nombre>.corrupto` en vez de dejar que la siguiente escritura lo borre. Todo lo que se guarda (historial, preferencias, voces, `.blocks.json` y `.txt`) pasa por aquí.

### Título y encabezado (solo desde el menú)

Con `titulo` (y `fecha`) el procesador nombra el archivo `AAAA-MM-DD Título.blocks.txt` (con `(2)`, `(3)`… si ya existe) y el `.txt` empieza con un encabezado (`# Título`, Fecha, Duración, Participantes; las líneas sin dato se omiten) seguido de una línea en blanco. El `.blocks.json` guarda entonces las claves `titulo`, `fecha` (AAAA-MM-DD) y `duracion`, para rehacer el encabezado al poner nombres (los participantes salen de ahí); las `huellas` ({"Hablante 1": [...]}) se guardan siempre que haya. **Sin título** (línea de comandos, Grabador, `.json` antiguos) esas claves no se escriben, no hay encabezado y el archivo se llama `<nombre del audio>.blocks.txt`, como antes. `cargar_transcripcion` acepta `.json` sin estas claves.

### Contrato con el Grabador (no romper)

La app Grabador de Max llama `transcriptor transcribir <archivo> -d --sin-preguntas -o <carpeta>` y luego lee `<nombre del audio>.blocks.txt`. `tests/test_grabador.py` fija esa llamada de punta a punta: mismo nombre de archivo, formato `[HH:MM:SS] Hablante: texto` separado por líneas en blanco, sin encabezado, sin preguntas ni notificaciones, y sin nombres automáticos por voz. Con `--sin-preguntas` (o sin terminal interactiva) nada debe preguntar ni cambiar. El comando `en-fila` (clic derecho) es aparte y no cambia `transcribir`. Con `--sin-preguntas` tampoco se ofrece revisar frases dudosas. No añadas flags obligatorios ni cambies esos nombres sin hablarlo con Max.

## Tests

`tests/conftest.py` reemplaza `mlx_whisper` en `sys.modules` (usa el fixture `mlx_transcribe` para simular la transcripción), bloquea `yt_dlp` real, apunta `TRANSCRIPTOR_HOME` a una carpeta temporal y hace que todos los tests corran "como en un Mac con chip Apple" (`plataforma.*` devuelve `True`). Para probar otra plataforma, sobrescribe esos `monkeypatch` en el test. El fixture `sin_red_ni_modelos_en_el_menu` hace que el menú no consulte la red ni la caché real de modelos (todo descargado, sin versión nueva); los tests de `menu` lo piden con `pytestmark`.

## Instalación para usuarios

`instalar.sh` (Mac/Linux) e `instalar.ps1` (Windows) instalan uv si falta, bajan el zip de `main` (la rama va fija en la constante `ZIP`/`$Zip`; no aceptan otra rama) con curl/PowerShell y hacen `uv tool install` desde ese archivo con el extra `[diarizacion]`; luego piden el `HF_TOKEN` opcional y lo guardan en `~/.transcriptor/.env`. Lo que se sube a `main` es lo que instalan los usuarios. Para probar la beta (rama `v2`) el README explica un `uv tool install` directo desde `.../archive/refs/heads/v2.zip`.
